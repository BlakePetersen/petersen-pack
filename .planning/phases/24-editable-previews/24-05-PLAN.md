<deferred>
**Prop → preview live wiring is deferred.** The registry's `preview(variant?: string)` only accepts a variant string. Threading the full `Record<string, string>` of form values into the preview renderer requires extending `ComponentDef.preview` to accept a props object — a registry-wide signature change that is out of scope for this phase. This plan delivers:
- Controlled form state
- URL encode via pushState (debounced)
- URL decode + hydration on mount
- Registry-default preview render

What is NOT delivered here: changing a form value and seeing the preview canvas re-render with that value applied. ARTAX-08 is still partially satisfied by the URL-shareable props-form + JSX editor (when spike passes). Full wiring is a candidate for a separate follow-up plan (24-0X) or a future phase that extends the preview signature.

**ROADMAP alignment note:** ROADMAP success criterion #2 — "component previews accept user-editable props/data that update the preview in real time" — is partially satisfied by the JSX editor path (plan 24-06, when spike passes), since the LiveProvider re-renders the preview on every keystroke. The props-form path does NOT satisfy real-time preview updates in this plan. The phase must be understood as: "real-time preview updates land via the JSX editor if the spike passes; the props-form ships URL-shareable state only." If the spike fails, ROADMAP success criterion #2 is NOT fully met by this phase and needs escalation before `/gsd-verify-work`.
</deferred>
